 # CAAI-BDSC2023 社交图谱动态链接预测 — 双路线预测 & 用户画像
 
 ## 项目背景

 本项目来源于 **阿里云天池竞赛 CAAI-BDSC2023 社交图谱链接预测** 的 **任务二：社交图谱动态链接预测**。任务目标为：基于历史社交分享行为数据，预测未来时间窗口内用户之间是否会
      围绕特定商品产生分享（链接）行为。

 在此基础上，项目额外扩展了两个自定任务：
 - **用户画像分析**：对预测出的回流用户（V 类用户）进行多维度画像刻画
 - **A/B 测试方案设计**：为商业决策提供统计推断支撑

 ## 核心思路

 ### LightGBM + GNN 双路线预测

 本项目的技术路线采用 **双模型融合** 策略：

 | 路线 | 方法 | 思路 |
 |------|------|------|
 | **路线一** | **LightGBM** | 将图结构特征（节点度数、共同邻居数、Jaccard 相似度、Adamic-Adar 等）展开为表格特征，用梯度提升树进行分类预测 |
 | **路线二** | **GNN (Graph Neural Network)** | 直接对社交图谱建模，利用 GCN / GAT / GraphSAGE 等图神经网络学习节点的低维嵌入表示，捕捉高阶拓扑关系 |

 两条路线的预测结果通过 **集成融合（Ensemble）** 得到最终链接预测分数，兼顾：
 - LightGBM 对稀疏特征的鲁棒性及训练效率
 - GNN 对图拓扑结构的深度建模能力

 ### 回流用户画像

 完成链接预测后，识别出 **回流用户 V**（即被预测将在未来时间窗口内产生分享行为的 voter），结合其特征（性别、年龄、用户等级）和行为模式，输出结构化的用户画像报告，服务于商业
      决策。

 ## A/B 测试方案概要

 ### 为什么要做 A/B 测试

 A/B 测试是数据驱动决策的核心工具。在本项目中，预测出回流用户 V 后，商业团队可能希望针对这些用户采取干预策略（如优惠券推送、个性化推荐）。A/B 测试可以科学评估干预策略的实际
      效果，避免"拍脑袋"决策。

 ### 本项目的 A/B 测试框架

```
实验目标：评估「针对预测回流用户的定向优惠券策略」能否提升分享转化率

实验单元：用户级（predicted voter）
分流比例：对照组 50% / 实验组 50%
实验周期：2 周

对照组 (Control)  ：不推送任何干预，自然观察分享行为
实验组 (Treatment)：推送定向优惠券，观察分享行为变化

核心指标：
   - 主指标：分享转化率（分享次数 / 用户数）
   - 辅助指标：人均分享次数、商品点击率

 统计学方法：
   - 假设检验：双样本 Z 检验 / 卡方检验（比例类指标）
   - 置信区间：95% CI for difference in proportions
   - 样本量公式：n = (Z_α/2 + Z_β)² × 2p(1-p) / δ²
   - 置信区间：95% CI for difference in proportions
   - 样本量公式：n = (Z_α/2 + Z_β)² × 2p(1-p) / δ²
 ```

 ### A/B 测试实施步骤（针对数据分析面试）
 
 1. **定义指标**：明确 OEC (Overall Evaluation Criterion)，区分主指标与护栏指标
 2. **计算样本量**：给定 MDE=2%, α=0.05, Power=80%，反推所需最小样本量
 3. **随机分流**：通过哈希分流保证实验组与对照组的同质性
 4. **AA 校验**：实验前用历史数据验证分流均匀性
 5. **监控与分析**：实验期间监控指标变化，实验结束后进行显著性检验
 6. **得出结论**：基于 p 值和置信区间给出业务建议（是否推广策略）

### 数据加载合并方案
第 1 步：高效加载大 JSON

  这几个 share 文件都很大（item_share_train_info.json 超 100MB），直接 json.load() 会把内存打爆。推荐两种方式：

  - 方案 A（推荐）：用 pandas.read_json() 配合 chunksize 逐块读取，或用 lines=True 如果数据是每行一条记录（当前看是标准 JSON 数组，所以用 pd.read_json() 配合 orient='records' 即可，pandas 内部有优化）
  - 方案 B：用 ijson 做流式解析，适合超大文件

  对于当前规模（百 MB 级），pandas 直接读应该能扛住，但如果内存紧张，可以上 chunksize。

  第 2 步：统一格式

  ---
  15 个新特征，按"洞察方向"分 7 组

  1. 时间新鲜度 — days_since_last_activity
  
  ▎ 距训练截止日（2022-12-06）多少天没活动了

  为什么有用：一个人 300 天没出现和 3 天前刚来过，回流概率显然不同。这是流失风险的最强信号。

  2. 角色分 — role_score（0~1 连续值）

  ▎ 0 = 纯消费者（只被分享），1 = 纯分享者

  为什么有用：比"活跃分享者 yes/no"更精细。0.3 和 0.7 是两种人。

  3. 交互深度 — out_repeat_ratio / avg_out_per_voter

  ▎ 是给 100 个人各分享 1 次，还是给 5 个人各分享 20 次？

  为什么有用：后者有固定社交圈，更可能回流同一个人。

  4. 时间规律 — weekend_ratio / night_ratio

  ▎ 这个人喜欢周末活动还是工作日？是夜猫子吗？

  为什么有用：非直觉洞察。比如"夜猫子回流率更高"是你看数据之前猜不到的。

  5. 品类偏好 — cate_entropy_out / top_cate_ratio_out

  ▎ 兴趣广泛（熵高）还是极度专注某一类（top ratio 高）？

  为什么有用：兴趣广的人可能更容易被各类商品吸引回流。

  6. 内容多样性 — item_diversity_out

  ▎ 是每次都分享同样几个商品，还是每次分享新东西？

  为什么有用：配合品类特征，能区分"探索型用户"和"习惯型用户"。

  7. 爆发度 — burstiness_out（-1~1）

  ▎ 值 >0 = 集中某几天疯狂分享然后沉寂，值 <0 = 每天稳定少量分享

  为什么有用：稳定型用户回流模式可预测，爆发型用户回流难以预测但可能量大。

  你现在有两张表：user_profile.pkl（29 特征）和 user_profile_enriched.pkl（44 特征）。后续做链接预测的时候：

  - GNN：初始节点特征就用 enriched 表的数值列（归一化后）
  - 跑完模型后：用 SHAP 看 Top 特征 → 这就是你的用户画像洞察 → 指导 AB 测试
