# 模型数据维度规格书

## A. LightGBM — 119维表格特征

### 特征分组

| 特征类别 | 维度 | 来源 | 对MRR的作用 |
|----------|------|------|-------------|
| 人口统计 | 6 (3×2面) | inviter/voter 的 gender, age, level | 低 — 身份属性,无法区分具体商品推荐 |
| 分享行为(发出) | 14 (7×2) | inviter/voter 的 share_out_count, unique_item, active_days... | 中 — 反映用户的分享活跃度和广度 |
| 接收行为(收到) | 14 (7×2) | inviter/voter 的 share_in_count, unique_item, unique_inviter... | 中 — 反映用户作为接收方的行为模式 |
| 图中心性 | 8 (4×2) | inviter/voter 的 degree, pagerank, share_ratio | 中 — 图结构中的重要性, 高PageRank节点更可能被分享 |
| 活跃状态 | 6 (3×2) | is_active_sharer, is_active_target, share_ratio | 中 — 用户当前的活跃程度 |
| 时效特征 | 6 (3×2) | days_since_last_share/receive/activity | 高 — 最近一次互动距今天数, 对排序有直接影响 |
| 重复互动 | 8 (4×2) | out_repeat_ratio, avg_out_per_voter, avg_in_per_inviter | 高 — 反映用户与固定对象的互动频率 |
| 品类偏好 | 6 (3×2) | cate_entropy_out, cate_diversity_out, top_cate_ratio_out | 中 — 用户的品类广度 vs 专注度 |
| 品牌偏好 | 6 (3×2) | brand_entropy_out, brand_diversity_out, top_brand_ratio_out | 中 — 用户的品牌广度 |
| 商品偏好 | 4 (2×2) | item_diversity_out, item_diversity_in | 低 — 商品级别的广度 |
| 时间模式 | 4 (2×2) | weekend_ratio, night_ratio | 低 — 用户的时间行为模式 |
| 行为新颖度 | 4 (2×2) | burstiness_out, burstiness_in | 低 — 行为集中度 |
| 用户质量 | 8 (4×2) | share_success_rate, network_growth_rate, activity_trend, response_latency | 中 — 用户的分享效果和增长趋势 |
| 角色特征 | 2 (1×2) | role_score (分享者型 vs 接收者型) | 中 — 用户的社交角色定位 |
| 品类交叉 | 8 (4+4) | pref_cate_inviter, pref_cate_voter (交叉视角) | 中 — 一方视角下另一方的品类偏好 |
| 物品信息 | 5 (4cat) | cate_id, cate_level1_id, brand_id, shop_id, cate_virality_score | 低 — 商品元信息, SHAP排名105-109 |
| 边特征 | 6 | is_friend, share_count_a2b/b2a, total_interactions, last_share_days, response_rate | **极高(场景1)** — 直接决定"这人是不是好友" |
| 图拓扑 | 4 | common_neighbors, jaccard, adamic_adar, pref_attachment | 中 — 结构接近度, LGB独有 |

### LGB 特征的使用情况

```
全部 119 维特征 = 14 分类 + 105 数值

LGB-A (无朋友圈): 113 维 → AUC 0.8957, MRR 0.5606
LGB-B (全特征):   119 维 → AUC 0.8606, MRR 0.4291  (边特征反而降低了AUC)
LGB-C (删is_friend): 118 维 → AUC 0.8555, MRR 0.4560
```

说明：边特征(is_friend等)在 AUC 上是负面的(因为正负样本各25%都有is_friend=1)，但在 MRR 场景1中 is_friend 是决定性特征。

## B. GNN — 图结构 + 节点特征 + ItemEncoder

### GNN 的输入结构

```
输入1: 图结构
  - 109,158 个用户节点
  - 602,606 条有向边 (inviter→voter, 训练期去重)
  - 2层 GraphSAGE 卷积 → 每个用户 → 64维 Embedding

输入2: 节点特征 (52维)
  - 来自 user_profile_enriched.pkl
  - 与 LGB 的用户画像大致相同, 但是用户级别(非样本级别)
  - 标准化后直接作为 GNN 初始特征

输入3: ItemEncoder (4维→32维)
  - cate_id    (7,504种)  → Embedding 8维
  - brand_id   (71,183种) → Embedding 8维
  - shop_id    (130,025种)→ Embedding 8维
  - cate_virality_score    → 标量 1维
  - 投影: 25维 → 32维

合并: LinkPredictor([inv_emb(64) || voter_emb(64) || item_emb(32)]) → 160维 → MLP → 分数
训练: BCE Loss, 1:3 负采样, 50 epochs
```

### GNN 缺失的信息

| LGB有但GNN没有 | 维度 | 对MRR的影响 |
|---------------|------|-------------|
| inviter_*/voter_* 展开特征 | 96维 | 高 — 样本级的用户对比信息 |
| 边特征 (is_friend, share_count...) | 6维 | **致命** — GNN无法直接知道"这俩人是不是好友" |
| 图拓扑 (CN, Jaccard, AA, PA) | 4维 | 中 — 图结构接近度 |
| 用户-品类深层交互 | 38维 | 中 — 品类偏好交叉 |
| per-(voter, item) 匹配特征 | 0维 | **致命** — 无法判断"这个人是否适合这个商品" |

### GNN ItemEncoder 的致命缺陷

```
MRR评估时, 同一查询的所有候选人收到相同的 item_emb:

  score_i = MLP([inv_emb || voter_i_emb || SAME_item_emb])

item_emb 对所有候选人是常数 → 排序完全由 user embedding 决定
→ item 信息对候选人排序的贡献为 0
```

## C. DySAT — GNN + 时序Attention

### 与 GNN 的差异

```
输入: 与 GNN 完全相同 (52维节点 + 图边 + ItemEncoder)
增加: TemporalAttention 层

TemporalAttention:
  - 2个快照的节点嵌入 → Multi-head Self-Attention (4头) → 64维
  - 快照1: ≤2022-10-29 (训练期, 144,869边)
  - 快照2: ≤2022-12-06 (训练+决赛, 155,716边)

问题:
  - 快照间仅新增 10,847 条边 (7%)
  - 71.3% 的用户度数在两个快照间完全不变
  - 时间跨度仅 38 天
  → 时序信号极弱, DySAT 无法学到有意义的时序pattern
```

### DySAT 效果

| 配置 | MRR@5 | vs GNN |
|------|-------|--------|
| GNN (无item) | 0.2137 | baseline |
| DySAT (无item) | 0.2219 | +3.8% |
| GNN + item | 0.3273 | baseline |
| DySAT + item | 0.3111 | **-5.0%** ← 加了item后反而退步 |

结论：时序信息在此数据集上基本无用。

## E. MRR 上不去的主因分析

### 当前特征能回答的问题

```
[✓] 这个人是谁?           → user profile (LGB 96维, GNN 52维)
[✓] 这俩人关系如何?        → edge features (LGB 6维, GNN 无)
[✓] 结构上近不近?          → topology (LGB 4维, GNN 无)
[✓] 这商品是什么?          → item info (LGB 5维, GNN 4→32维)
[✓] 这个人活跃吗?          → behavior (LGB 38维, GNN 部分)
[✗] 这个人喜欢这个品类吗?   → **完全缺失**
[✗] 这个人和这个商品匹配吗? → **完全缺失**
```

### 为什么现有特征不够

1. **is_friend 是过滤器，不是排序器**：is_friend=1 能把好友排到路人前面(场景1 MRR=0.74)，但面对10个好友候选人，is_friend 对所有人都是1——无法区分谁该排第一。

2. **物品特征太粗**：cate_id/brand_id/shop_id 对排序没有区分度——同一品类下有成千上万商品，知道品类不等于知道该推给谁。

3. **GNN 的 ItemEncoder 对排序无效**：所有候选人共享同一个 item_emb，排序完全由 user embedding 决定。

### 缺失的关键特征

```
voter_received_same_cate_count       这个voter收过几次 当前item的品类
voter_received_same_brand_count      这个voter收过几次 当前item的品牌
voter_last_received_cate_days        这个voter最近收这个品类是几天前
voter_cate_affinity_score            voter对这个品类的偏好度 (tf-idf)
inviter_friends_in_cate_count        在inviter好友中, 多少人收过这个品类
voter_rank_in_friends_for_cate       在inviter好友中, 该voter收该品类的排名
voter_received_from_inviter_count    这个voter从这个inviter那里收过多少次
voter_item_recency                   这个voter最近一次收任何item是何时
```

这些特征把"谁适合收这个商品"直接编码进特征空间。当前119维里一个都没有。
