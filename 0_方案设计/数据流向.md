friend_circle[inviter_id] = {voter_id_1, voter_id_2, ...}

| 特征 | 说明 | 典型值 |
|------|------|--------|

| share_count_a2b | A→B分享次数 | 均值2.6, 中位数1 |

| total_interactions | a2b + b2a | |
| last_share_days | A→B最近分享距截止日的天数 | |
| response_rate | b2a / a2b, B回流A的比例 | 79%的边为0(无回流) |

### 4.3 双向好友率分析

每个inviter的朋友圈中, 有多少比例的朋友也反过来分享过。完全单向(率=0)占大多数, 完全双向(率=1)极少 → 社交关系高度不对称。

### 4.4 预分析结论 (朋友圈加权策略的实证依据)

- 分享次数越多 → 回流率越高 (剂量-响应关系)
- 最近互动越近 → 回流率越高 (时间衰减效应)
- 结论: 朋友圈加权策略有实证支撑

## 五、阶段4: 训练矩阵构建

**文件:** `2_标签构造和数据清洗/build_train_matrix.py`

这是整个pipeline中最核心的一步: 把原始分享记录变成LightGBM可以直接训练的表格。

### 5.1 时间切分

```
训练集: 2021-12-27 ~ 2022-10-28 (约60万行, 占83%)
验证集: 2022-10-29 ~ 2022-12-06 (约12万行, 占17%)
分界线: 2022-10-29 (share_train 与 share_final_train 的自然断点)
```

**为什么按时间切分而不是随机?** 社交行为在时间上自相关——用"过去"预测"未来"才符合真实场景。随机切会让模型看到"未来数据"再预测"过去", 导致过拟合假象。

### 5.2 标签构建

```python
正样本 (label=1): 真实发生过的分享 — 从训练数据直接提取 (inviter, item, voter, timestamp)
负样本 (label=0): 随机采样的未回流voter — 用向量化负采样算法生成
负采样比例: 1:3 (每条正样本配3条负样本)
```

**负采样算法核心逻辑:**
1. 为每条正样本按 `(inviter, item)` 对找所有真实voter → 全部排除
2. 从全局voter池随机采样 (向量化一次性生成 N×(3+10) 个随机索引)
3. 过滤排除列表 → 取前3个 → 用 `np.repeat` 构造DataFrame
4. 87.3%的 `(inviter, item)` 对只有一个voter, 12.7%有多个 → 全部排除, 保证标签干净

**训练集最终规模:** 60万×4 = 240万行 (含正负样本)
**验证集最终规模:** 12万×4 = 48万行

### 5.3 特征拼接 (4次MERGE)

每条样本行 (inviter, item, voter) 拼接以下特征:

```
第1步: inviter侧用户画像 (53维 → inviter_xxx)
        df_profile JOIN ON user_id = inviter_id

第2步: voter侧用户画像 (53维 → voter_xxx)
        df_profile JOIN ON user_id = voter_id

第3步: 商品特征 (cate_id, brand_id, shop_id等5维 + cate_virality_score)
        item_info JOIN ON item_id

第4步: 边级朋友圈特征 (is_friend, share_count_a2b等6维)
        df_edge_train JOIN ON (inviter_id, voter_id)

第5步: 图拓扑特征 (common_neighbors, jaccard, adamic_adar, pref_attachment 4维)
        仅对图中真实边(~20万对)计算, 非图中边直接填0
```

### 5.4 图拓扑特征详解

| 特征 | 公式 | 直觉 | 计算策略 |
|------|------|------|----------|
| common_neighbors | |N(A) ∩ N(B)| | 共同联系人越多 → 越可能产生新链接 | 仅算真实图边(~20万对) |
| jaccard | |N(A)∩N(B)| / |N(A)∪N(B)| | 归一化的重叠度, ∈[0,1] | 非图中边直接填0 |
| adamic_adar | Σ 1/log(deg(z)) for z∈N(A)∩N(B) | 共有的"冷门联系人"权重更高 | 度低的共同邻居信号更强 |
| pref_attachment | deg(A)×deg(B) / total_edges | 度数高的人之间更易产生链接 | 对所有对都有值 |

**性能优化:** 280万行里很多(inviter, voter)重复(同一对人, 不同商品)。先对唯一配对(~20万对真实边)计算拓扑特征, 再merge回全表。精度无损, 速度提升10倍以上。

### 5.5 缺失值处理原则

```
数值特征缺失 → 填 0       ("没有"与"有但值为0"在语义上等同)
类别/身份缺失 → 填 -1     ("未知"与正常值(0/1/2...)区分开)
时间特征缺失 → 填 -1      ("从未发生过"与正常时间值区分开)
```

**为什么不用均值填充?** "从未分享过"(缺失) vs "分享了但成功率很低"(值为0.05) — 这是两种人, 用均值填充等于混为一谈, 信号丢失。

## 六、阶段5: LightGBM基线建模

**文件:** `3_算法建模/lgb_baseline.py`

### 6.1 AB测试设计

| 组 | 特征维度 | 说明 |
|----|----------|------|
| A (基线) | 113维 | 删除全部6个边级朋友圈特征, 仅保留拓扑特征 |
| B (实验) | 119维 | 全保留, 含 is_friend + 5个连续边级特征 |
| C (实验) | 118维 | 保留5个连续边级特征, 删除 is_friend(硬开关) |

### 6.2 模型配置

```python
LGBMClassifier(
    objective='binary',
    metric='auc',
    is_unbalance=True,   # 自动处理1:3不平衡
    random_state=42,
    n_jobs=-1,
)
```

### 6.3 评估指标

| 指标 | 说明 | 竞赛官方基线 |
|------|------|-------------|
| AUC | ROC下面积, 衡量排序质量 | — |
| MRR@5 | Mean Reciprocal Rank, true voter排第n得1/n分, 不在top-5得0 | 0.03437 |
| HITS@5 | true voter出现在top-5的比例 | 0.09258 |

### 6.4 MRR@5 计算流程

```python
对每个验证集查询 (inviter, item, timestamp):
  1. 构造候选voter池 = 该inviter的全部训练期朋友 + 200个随机补充
  2. 拼接全部特征 (inviter+item+voter+边+拓扑)
  3. 用LightGBM对所有候选打分
  4. 按分数降序排列, 看true voter排第几名
  5. MRR = mean(1/rank) for rank≤5 else 0
```

## 七、阶段6: MRR分场景拆解

**文件:** `3_算法建模/mrr_breakdown.py`

### 7.1 拆解逻辑

将验证集查询按 `true_voter 是否在训练期朋友中` 分成两个场景:

| 场景 | 占比 | 含义 | is_friend的作用 |
|------|------|------|-----------------|
| 场景1: true是训练期朋友 | 72.4% | 老朋友回流 | is_friend有帮助(但候选池已经全是朋友, 区分度有限) |
| 场景2: true不是训练期朋友 | 27.6% | 新朋友首次互动 | is_friend直接误导(对新朋友永远返回0) |

### 7.2 关键发现

```
is_friend 是"过滤器"而非"排序器":
  - 场景1: B模型MRR=0.74, 朋友池里还要区分出最可能的那一个
  - 场景2: B模型MRR暴跌到~0.05, 因为is_friend对新朋友永远=0
  - A模型不受is_friend干扰, 场景2 MRR=~0.14
```

### 7.3 对建模的指导意义

- is_friend不能作为输入特征(测试集天然缺这个信号)
- share_count_a2b/total_interactions/response_rate等连续型边级特征更有价值
- 用户画像特征可以覆盖新朋友冷启动场景
